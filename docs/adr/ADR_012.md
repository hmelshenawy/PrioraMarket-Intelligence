# ADR-012: Replay Dataset Identification Strategy

**Status:** Accepted (Temporary)

**Date:** 2026-07-04

---

## Context

Feature 001 introduced offline replay capability that rebuilds normalized listings from previously stored Raw Listings.

The replay CLI currently accepts the argument:

```bash
replay --dataset <identifier> --normalization-version <version>
```

During validation, the following behavior was observed:

```bash
replay --dataset dataset_2026_07_04_001
```

Result:

```
No raw listings found for dataset dataset_2026_07_04_001
```

However,

```bash
replay --dataset run_dubizzle_used_mercedes-benz_f352ddab
```

successfully rebuilt all stored listings.

Investigation showed that Raw Listings are currently stored beneath the ingestion run directory:

```
data/
└── dubizzle/
    └── run_dubizzle_used_mercedes-benz_f352ddab/
        ├── raw_listings.jsonl
        ├── listings.csv
        └── run_report.json
```

The replay implementation therefore resolves storage using the **Run Identifier**, not the **Dataset Version**.

This creates a mismatch between the CLI contract and the implementation.

---

## Problem

The CLI suggests that replay operates on Dataset Versions.

The implementation actually operates on Run Identifiers.

As the platform evolves toward:

- Dataset Versioning
- ML Training
- Historical Analytics
- Multiple Marketplaces

this distinction becomes important.

A Dataset Version represents a logical dataset.

A Run Identifier represents one ingestion execution.

They are related but are not conceptually equivalent.

---

## Options Considered

### Option A — Rename the CLI

Rename:

```text
--dataset
```

to

```text
--run-id
```

### Advantages

- Matches current implementation.
- Minimal development effort.
- No additional lookup required.

### Disadvantages

- Exposes an internal implementation detail.
- Couples replay to ingestion runs.
- Becomes less suitable when a Dataset Version is composed from multiple runs.

---

### Option B — Introduce Dataset Index (Preferred Long-Term)

Maintain the existing CLI:

```text
--dataset
```

Introduce a Dataset Index that maps:

```
Dataset Version
        │
        ▼
One or More Run Identifiers
        │
        ▼
Stored Raw Listings
```

Replay resolves the Dataset Version first and then loads all associated Raw Listings.

### Advantages

- CLI remains domain-oriented.
- Supports future Dataset Versioning.
- Compatible with ML pipelines.
- Compatible with multiple marketplaces.
- Supports datasets built from multiple ingestion runs.

### Disadvantages

- Requires additional metadata management.
- Slightly more complex implementation.

---

## Decision

Feature 001 will continue using Run Identifiers internally.

The existing CLI remains functional for development purposes.

The mismatch between the parameter name and implementation is accepted temporarily.

Feature 002 (Database Persistence Foundation) will introduce Dataset persistence and metadata.

At that point the replay interface will be revisited.

---

## Consequences

Current implementation:

```
Replay
   │
   ▼
Run Identifier
   │
   ▼
Raw Listings
```

Target architecture:

```
Replay
   │
   ▼
Dataset Version
   │
   ▼
Dataset Index
   │
   ▼
Run Identifiers
   │
   ▼
Raw Listings
```

No breaking changes are required for Feature 001.

Future replay implementations should operate using Dataset Versions rather than storage-specific Run Identifiers.
